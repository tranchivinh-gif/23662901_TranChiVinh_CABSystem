NHỮNG ĐIỂM CẦN XÁC NHẬN
=======================

- Requirement chưa rõ: công thức cước, tiêu chí tìm tài xế, quy tắc hủy và hoàn tiền, thời gian retry thanh toán, KPI báo cáo.
- Use Case chưa rõ: UC-17 đến UC-19 chưa có endpoint hoặc mô tả rõ trong API Document.
- Chức năng chưa rõ: loại dịch vụ, kênh thông báo cụ thể, cấu hình provider, thời gian lưu trữ vị trí/audit.
- API chưa xác định thuộc chức năng nào: một số API phụ thuộc vào business rule chưa được chốt rõ.
- Hai API có khả năng thuộc cùng một chức năng nhưng chưa đủ thông tin để gộp: API thanh toán điện tử, API thông báo, API vận hành cần xác nhận phạm vi MVP.
- Business Rule chưa rõ: chính sách hủy, khóa hủy, retry thanh toán, quyền truy cập, lưu vết và bảo mật dữ liệu.
- Validation chưa rõ: định dạng dữ liệu vị trí, độ chính xác GPS, giới hạn loại xe, đánh giá tài xế, và các quy tắc báo sự cố.
- SRS và API Document mâu thuẫn: các nội dung đánh dấu [NEED CLARIFICATION] hoặc [Cần làm rõ] vẫn tồn tại trong MVP baseline.
- Không xác định được phạm vi của một Scenario: các chức năng mở rộng (báo cáo KPI, provider thông báo, tích hợp thanh toán, audit) có thể nằm ngoài phạm vi đồ án nhỏ.
- Priority được xác định theo baseline MVP trong SRS: High cho luồng cốt lõi của dịch vụ đặt xe và Medium cho chức năng hỗ trợ vận hành, thông báo, sự cố và báo cáo.
